# Web 工作台 分阶段开发计划

## 0. 总原则

1. **阶段叠加、可独立验收**：每个阶段结束时产品都是可运行、可演示的，不做"全部写完再联调"。
2. **每个阶段先跑通最窄闭环再扩展**：例如阶段 1 只做"注册→登录→建项目→列表隔离"，不提前铺成员与权限。
3. **未完成项不勾选、不声称完成**：每个阶段末尾的验收必须真实执行并记录结果（命令、输出、截图或页面现象）。
4. **文档先行**：改动影响 PRD 行为时先更新 PRD，再改代码。

> 前端工程说明：业务界面是 DSH 插件的一部分（架构 v2），因此"前端开发"= 在 `fde-workbench-bundle/src/client/` 内开发 React 组件并构建插件 bundle；Java 后端不再托管任何页面。

阶段依赖关系：

```text
阶段0 骨架
  └─ 阶段1 用户与项目中心
        └─ 阶段2 成员与权限
              ├─ 阶段3 技能
              └─ 阶段4 流程
                    └─ 阶段5 需求与实例
                          └─ 阶段6 会话与节点闭环   ← 核心，依赖插件
                                └─ 阶段7 联调收口
```

## 阶段 0：工程骨架与插件骨架

**目标**：前后端与插件都能启动，插件入口能在 DSH 中出现，并打开空白业务页。

**产出**

| 项 | 位置 | 说明 |
|---|---|---|
| Maven 多模块 | `workbench/` | parent + common/dao/service/api/app |
| 数据库迁移 | `workbench/workbench-app/src/main/resources/db/migration/` | 直接使用 `docs/database/001_init.sql` 作为事实源；Flyway 采用 `V1__init.sql` 版本号但内容由脚本生成并校验一致（目标 MySQL 5.7 不支持部分 8.0 语法，脚本已按 5.7 编写） |
| 健康检查 | `/api/health` | 返回版本、数据库连通性 |
| 业务前端骨架 | `fde-workbench-bundle/src/client/` | 页面栈、GitHub 风格基础组件、API 层；不再有独立 SPA 工程 |
| 插件包 | `fde-workbench-bundle/` | `package.json` + `cordis.patch.yml` + Host 空 apply + Client 侧栏面板入口与 `main` 面板 |
| 会话嵌入冒烟用例 | `fde-workbench-bundle/src/client/session/` | 用 `conversation.content` 工厂 + `sessions.retain` 渲染一个真实会话，验证尺寸、滚动、快捷键 |

**验收**

1. `mvn -q -DskipTests package` 成功，`java -jar workbench-app.jar` 启动后 `GET /api/health` 返回 200。
2. 插件 bundle 构建成功并安装。
3. 安装插件后重启 DSH：侧栏面板列表第一行出现「Web 工作台」，点击后 `main` 面板显示工作台空壳，页面不跳转。
4. **会话嵌入冒烟用例通过**：面板内能渲染一个真实 DSH 会话，消息流可见、可输入、可滚动，`Esc Esc` 停止仍生效。
5. 禁用插件：DSH 界面恢复原样，无报错。

**风险**：会话嵌入的尺寸/滚动/快捷键行为需实机确认（[plugin-integration.md §8 R2、§9 待验证](plugin-integration.md)）。

## 阶段 1：用户与项目中心

**目标**：能注册、登录，创建项目，且列表只展示自己的项目。

**后端**

- `workbench-common`：统一返回体、错误码、JWT 工具、全局异常。
- `auth`：注册（用户名可选密码）、登录、`/me`；BCrypt。
- `project`：创建、列表、详情、编辑、删除；创建事务内写入 `wb_project_member(role=owner)`。
- `JwtAuthFilter`。

**前端**

- 登录/注册页（同一页面切换）。
- 项目中心：列表卡片、创建对话框、搜索。

**验收**（对应 REQ-H1、REQ-B1~B3）

1. 注册 `demo`（空密码）→ 自动跳到登录 → 空密码登录成功。
2. 未注册 `nobody` 登录 → 提示"用户不存在，请先注册"。
3. 创建项目 → 列表出现 → 详情页出现四个 Tab（其余为空状态）。
4. 用 `demo2` 登录 → 项目列表为空；直接访问 `demo` 的项目 URL → 403。

## 阶段 2：成员与权限

**目标**：owner 管理成员与转让；非成员被统一拦截。

**后端**

- 成员列表、添加、移除、转让 owner（事务）。
- `ProjectAccessAspect`：所有带 `projectId` 的业务方法校验成员身份。
- 数据归属校验：编辑/删除项目只允许 owner。

**前端**

- 成员 Tab：列表、添加、移除、转让确认对话框。
- 非 owner 隐藏管理按钮。

**验收**（对应 REQ-C1~C4、REQ-H2~H4）

1. `demo` 添加 `demo2` → `demo2` 侧出现该项目。
2. `demo2` 看不到添加/移除按钮，直接调接口返回 403。
3. 转让给 `demo2` → 角色互换 → `demo` 失去删除项目权限。
4. 移除 `demo2` → `demo2` 刷新后列表为空，访问该项目 403。

## 阶段 3：技能管理

**目标**：上传技能包、查看版本、下载、删除前引用校验。

**后端**

- 上传解包、`SKILL.md` 校验、`files_json` 与 `checksum` 计算。
- 同名升级版本；下载（按版本重打包 zip）；单文件预览。
- 删除前引用校验（流程模板引用 + 未完成实例快照引用）。

**前端**

- 技能 Tab：列表（名称、当前版本、引用数）、上传对话框、版本抽屉、下载。
- 删除时若被引用，弹窗展示引用清单。

**验收**（对应 REQ-D1、REQ-D2）

1. 上传含 `SKILL.md` 的 zip → 列表出现，版本 1。
2. 再次上传同名 → 版本 2，可下载 v1 与 v2。
3. 上传不含 `SKILL.md` 的 zip → 400 并提示。
4. 被未完成需求节点引用时删除 → 409 并列出引用位置。

## 阶段 4：流程管理

**目标**：流程 CRUD、节点上下拖动排序、节点展开编辑输入/输出/多技能。

**后端**

- 流程 CRUD；`PUT /nodes` 整体保存（含删除、新增、重排）。
- 节点多技能（`wb_workflow_node_skill`）。
- 删除流程的引用校验。

**前端**

- 流程 Tab：列表 + 流程编辑页。
- 节点列表：拖动排序（HTML5 DnD 或轻量库）、点击展开、内联编辑。
- 输入类型切换（自由/固定）；固定输入项增删；输出项增删；技能多选（带顺序）。

**验收**（对应 REQ-E1~E5）

1. 新建流程 → 添加 3 个节点 → 拖动第 3 个到第 1 位 → 保存后刷新顺序一致。
2. 节点选择 2 个技能 → 保存后回显顺序一致。
3. `itemKey` 重复 → 400 并定位到字段。
4. 被需求引用的流程删除 → 409。

## 阶段 5：需求与节点实例

**目标**：创建需求即生成实例快照，需求详情可查看节点流转。

**后端**

- 需求 CRUD；创建时事务生成节点实例（快照输入/输出/技能 + 版本号）。
- 需求详情：节点列表 + 权限标记。

**前端**

- 需求 Tab：列表、新建（选择流程）、详情。
- 详情页：节点时间线/列表，显示状态；点击节点进入节点信息页。

**验收**（对应 REQ-F1~F3、REQ-H4）

1. 创建需求 → 第一个节点为"进行中"，其余"未开始"。
2. 修改流程（增删节点、改输出项）→ 已有需求节点不变。
3. 他人打开我的需求 → 可查看，无编辑按钮；调编辑接口 403。

## 阶段 6：会话与节点闭环（核心）

**目标**：模型在真实对话中按节点要求产出，页面可见可下载，全部完成自动推进；会话可切换、新建、恢复。

**后端**

- 节点信息接口（上一节点输出、输入、输出、只读判定）。
- 输入上传（自由/固定）。
- `/internal/nodes/{id}/outputs/{key}/commit`：校验、登记、推进事务。
- 会话对应关系 CRUD 与默认会话解析。
- 文件下载与预览。

**插件 Client**

- 节点页 `RequirementPage`：会话 / 节点信息 视图切换。
- `NodeSessionView`：`sessions.retain` + `SessionProvider` + `conversation.content`。
- `SessionController`：默认会话解析、新建会话（`uiWorkspace.connectWorkspace` + `/internal/sessions` 登记）、失效处理。
- 会话切换器与「新建会话」顶部操作条。

**插件 Host**

- 4 个 Host 工具。
- 内置技能 `workbench-node-delivery`。
- 节点上下文 prompt 段。
- Host 路由 `/api/fde-workbench/session/{open,resolve}`（供外部入口）。

**前端**

- 节点信息页签（完整布局与只读态）。
- 会话页签：会话切换器（本需求会话列表 + 新建会话 + 当前节点绑定标识）。
- 输出提交后自动刷新；全部完成提示进入下一节点。

**验收**（对应 REQ-F4~F7、REQ-G1、REQ-X1、REQ-X2）

1. 当前节点、自由输入：上传 1 个文件 → 列表可见。
2. 固定输入节点：每个输入项右侧有上传按钮，上传后各自显示文件。
3. 在会话中要求模型产出 2 个输出项 → 模型调用 `node_output_write` 与 `node_output_commit` → 页面出现 2 个下载按钮。
4. 下载文件内容与模型产出一致（sha256 校验）。
5. 全部输出项完成后刷新 → 当前节点切换为下一节点。
6. 打开非当前节点 → 无会话页签、无上传按钮，下载仍可用。
7. 他人打开我的需求当前节点 → 与 6 相同。
8. 节点页内切换「会话 / 节点信息」两个视图，页面不跳转、不丢失滚动位置。
9. 节点 2 默认打开节点 1 用过的会话（历史完整）；点「新建会话」→ 新会话绑定节点 2 → 再进入节点 2 默认打开新会话。
10. 关闭 DSH 重开 → 进入需求 → 会话恢复，历史消息完整。

**风险**

- 模型不调用工具：通过技能措辞与 `node_context_get` 的"未提交项"提示迭代。
- 长对话导致上下文溢出：依赖 DSH 自带压缩；文档记录现象。

## 阶段 7：联调收口

**目标**：干净环境可一键部署，完整主流程可走通。

**产出**

- `README.md`：环境要求、构建、启动（MySQL / Java / 插件构建与安装）。
- 部署校验脚本：执行 DDL → 启动 → 健康检查。
- DSH 版本兼容说明表（实测版本、`order` 实际值、Slot 名）。
- 已知问题清单。

**验收**

1. 按 README 在干净目录一步步执行成功。
2. 从注册到需求完成的完整主流程无阻塞。
3. 记录一次完整走查（时间、步骤、结果）。

- 每完成一个阶段，停留在该阶段等待人工验收，不自动进入下一阶段。
