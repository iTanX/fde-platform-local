# 多格式文档拆分与转换

本技能只负责**业务规则**：怎么识别各段、怎么转换格式。

**产出物清单、输出项名称、写入路径一律以节点配置为准**——每轮先调用
`node_context_get` 查看【输出项】，按它给出的项与建议路径交付，
本技能不会、也不应该规定输出项叫什么。

## 1. 识别各段

文档里每一段内容都用代码块围栏包裹，围栏的**语言标识**就是这一段的格式：

- ` ```markdown ` 或 ` ```md ` → Markdown 段
- ` ```json ` → JSON 段
- ` ```yaml ` 或 ` ```yml ` → YAML 段

规则：

- 只处理围栏内部的内容，**不要**把围栏外的标题、说明文字写进输出文件。
- 一段可能有多个围栏，同语言的围栏内容按出现顺序合并成一份输出。
- 围栏顺序不影响输出项的对应关系：**按格式匹配**，不按第几段匹配。
- 找不到某种格式的围栏时，不要编造该格式的内容；在最后回复里说明缺哪一段。

## 2. 各格式的转换规则

### Markdown 段 → Markdown 文件

去掉最外层围栏，保留内部原有的标题层级与列表。可以在文件开头补一行
`<!-- 由多格式文档拆分生成 -->` 作为来源标记。不要改写正文措辞。

### JSON 段 → JSON 文件

- 解析后**重新序列化**，缩进 2 个空格，保持字段原有顺序。
- 原样保留字段名与值，不做重命名、不补默认值、不改数据类型。
- 如果 JSON 本身无法解析，**不要**输出一份"猜出来的"JSON；
  在回复里指出哪一行解析失败，并请用户确认。

### YAML 段 → Properties 文件（简单扁平化）

把嵌套结构逐层展开，用 `.` 连接各级键：

- 映射（map）：`parent.child=value`
- 序列（list）：用 `[下标]` 作键 → `regions[0].name=cn-east`
- 标量：直接按原值写出
- 布尔值写 `true` / `false`（小写）
- 字符串**不加引号**（Properties 的引号会被当成值的一部分）
- 每行一个键值对，`key=value`，等号两侧不加空格
- 空值写成 `key=`

示例：

```yaml
dispatch:
  strategy: weighted-round-robin
  regions:
    - name: cn-east
      weight: 60
```

转换后：

```properties
dispatch.strategy=weighted-round-robin
dispatch.regions[0].name=cn-east
dispatch.regions[0].weight=60
```

补充约定：

- 键的展开顺序**沿用 YAML 里的书写顺序**，便于人工比对。
- 值里含有换行时转义为 `\n`，含 `\` 时转义为 `\\`。
- 若 YAML 无法解析，同样不要猜测：指出问题位置并请用户确认。

## 3. 交付动作

格式转换完成后，按 `node_context_get` 返回的【输出项】逐项交付：

- 用 `node_output_write` 写入对应输出项（按格式判断该写进哪一项，参考输出项的类型与说明）。
- 写完**立即**用 `node_output_commit` 登记，不要攒着一起提交。
- 输出项要求的文件类型可能限制扩展名；若写入被拒，按工具提示的错误调整后重写。

## 4. 回复用户时说明

1. 识别到了哪几段（各自格式、大致行数）；
2. 每份产出对应哪个输出项、是否已登记成功；
3. Properties 转换后共多少行键值对；
4. 有没有无法解析或缺失的段落。
