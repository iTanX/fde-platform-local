# 基于 DeepSeek Harness 的 AI Web 工作台 PRD

## 1. 产品概述

### 1.1 一句话定位

以**项目**为顶层维度的 AI 协作工作台：团队成员在项目内定义流程、上传技能、提交需求；需求按流程节点推进，每个节点通过与 DeepSeek Harness 的原生会话多轮对话，让模型产出该节点约定的输出项，输出项落盘后可在页面查看与下载，全部完成即进入下一节点。

### 1.2 目标用户

| 角色 | 说明 | 核心诉求 |
|---|---|---|
| 项目 owner | 创建项目的人 | 管理项目一切：成员、技能、流程、需求 |
| 项目成员 | 被 owner 添加的普通成员 | 推进自己创建的需求；查看项目全部资料 |

### 1.3 核心价值

1. **流程可复用**：一个项目沉淀一套流程与技能，新需求直接复用，不必每次重新交代背景。
2. **产出可落地**：模型产出的不是聊天记录，而是被页面识别、可下载、跨会话跨节点持久保存的文件。
3. **协作有边界**：项目成员共享读取权限，但只能推进自己的需求，避免互相干扰。

### 1.4 与其他产品形态的区别

- 不是通用聊天工具：对话被绑定在"需求节点"这一执行单元内。
- 不改 DeepSeek Harness 源码：所有能力通过插件接入，保留 Harness 升级能力。

## 2. 范围

### 2.1 本期范围（P0）

- DSH 侧栏「Web 工作台」入口插件（全局面板列表第一行、会话列表上方），工作台为插件内原生页面。
- 用户注册、登录（用户名 + 可选密码，JWT）。
- 项目中心：项目增删改查，只展示当前登录人所属项目。
- 项目成员管理：owner 增删成员、转让 owner。
- 技能管理：手工上传技能包、版本、下载、删除前引用校验。
- 流程管理：流程增删改查；节点列表拖动排序；节点输入（自由/固定）、输出（固定）、可用技能（多选）。
- 需求管理：需求增删改查；创建时绑定流程并生成节点实例；需求详情按节点推进。
- 节点信息页：上一节点输出、节点输入（上传）、输出项（下载）、说明。
- 会话页签：DSH 原生会话，多轮对话，可切换/新建/恢复会话。
- 内置指导技能：每个节点默认注入，教模型如何产出与落盘。
- 权限：项目成员读取；owner 全权；成员只能推进自己的需求。

### 2.2 明确不做（本期）

| # | 不做 | 原因/后续 |
|---|---|---|
| N1 | 自由拖拽的流程画布 | 需求明确只要节点列表 |
| N2 | 技能在线编辑 | 需求明确先只支持手工上传 |
| N3 | 需求市场、跨项目资产复用 | 不在原始需求内 |
| N4 | 短信/邮箱验证、密码找回 | 注册仅需用户名 |
| N5 | 多人实时协同编辑（同一节点并发写） | 同一需求只有一个推进人 |
| N6 | 节点人工审批/回退操作面 | 自动推进；回退列为 P1 预留接口位 |
| N7 | 会话内容在业务库内二次存储 | 会话权威在 DSH，业务库只存对应关系 |

## 3. 术语

| 术语 | 定义 |
|---|---|
| 项目 | 数据顶层维度，包含需求、流程、技能、成员四部分 |
| 流程 | 有序的节点列表，是需求的执行模板 |
| 流程节点 | 流程中的一步，定义输入、输出与可用技能 |
| 需求 | 项目内的一次执行，绑定一个流程 |
| 节点实例 | 需求创建时按流程节点生成的快照，是实际执行单元 |
| 输出项 | 节点约定的固定产出，必须由模型生成并提交后才能推进 |
| 节点输入 | 该节点执行时提供给模型的资料；分自由输入与固定输入 |
| 会话 | DeepSeek Harness 原生会话，一次连续对话 |
| 当前节点 | 需求实例中正在执行的节点；其余节点只读 |
| 内置技能 | 随插件发布的指导技能，说明如何产出与落盘 |
| Revision | 可编辑聚合根的乐观锁版本号 |

## 4. 需求清单与验收

> 需求 ID 规则：`REQ-<分组编号>-<序号>`；分组 A=入口、B=项目中心、C=成员、D=技能、E=流程、F=需求与节点、G=内置技能、H=用户与权限、X=跨模块修正项。
> 验收采用 Given/When/Then；每条验收只对应一个可观察结果。

### A. 入口（DSH 插件）

#### REQ-A1 侧栏入口

- 来源：原始需求 §1
- 描述：在 DeepSeek Harness 界面左侧栏第一个选项的上方增加「Web 工作台」入口。

**AC-A1.1**
- Given DSH Web 已启动且工作台插件已启用
- When 打开 DSH 主界面
- Then 左侧栏顶部（原第一个选项之上）出现「Web 工作台」入口，且不遮挡或替换原有选项

**AC-A1.2**
- Given 工作台插件被禁用
- When 打开 DSH 主界面
- Then 界面与官方 DeepSeek Harness 完全一致，无任何残留元素或报错

#### REQ-A2 插件形式接入，不改 DSH 源码

- 来源：原始需求 §1、§开发要求 2
- 描述：以 DeepSeek Harness 插件形式增加入口，尽量与源码解耦，保留升级能力。

**AC-A2.1**
- Given 本项目交付物
- When 对比 DSH 官方安装目录与官方版本
- Then 官方文件无任何修改，工作台能力只存在于独立插件包目录

**AC-A2.2**
- Given DSH 升级到官方更新版本
- When 重新安装本插件包
- Then 「Web 工作台」入口与业务功能仍可用；若官方扩展点发生变化，插件在加载失败时给出明确诊断为不影响 DSH 原生功能

#### REQ-A3 点击进入项目中心

- 来源：原始需求 §2
- 描述：点击「Web 工作台」进入项目中心。

**AC-A3.1**
- Given 已登录
- When 点击「Web 工作台」
- Then 打开项目中心页面，展示项目列表

### B. 项目中心

#### REQ-B1 项目是数据顶层维度

- 来源：原始需求 §2
- 描述：数据以项目为顶层维度管理，项目包含需求管理、流程管理、技能管理、成员管理四部分。

**AC-B1.1**
- Given 打开一个项目
- When 查看项目页面
- Then 以横向 Tab 呈现「需求」「流程」「技能」「成员」四部分，切换 Tab 不离开项目

#### REQ-B2 项目增删改查

**AC-B2.1**
- Given 登录用户
- When 创建项目并填写名称
- Then 项目创建成功，创建人自动成为 owner 与成员

**AC-B2.2**
- Given 我是项目 owner
- When 编辑项目名称/简介
- Then 修改生效，列表与其他成员视图同步更新

**AC-B2.3**
- Given 我是项目 owner
- When 删除项目
- Then 项目从所有成员的项目列表中消失，二次确认后才执行

#### REQ-B3 只展示自己所属的项目

- 来源：原始需求 §8

**AC-B3.1**
- Given 我是项目 A 的成员、不是项目 B 的成员
- When 打开项目中心
- Then 列表只出现项目 A；直接访问项目 B 的地址返回无权限

### C. 成员管理

#### REQ-C1 owner 默认

- 来源：原始需求 §3
- 描述：项目创建人默认为项目 owner。

**AC-C1.1**
- Given 我创建了项目
- When 查看成员列表
- Then 我的角色显示为 owner，且只有一个 owner

#### REQ-C2 owner 增删成员

**AC-C2.1**
- Given 我是 owner
- When 按用户名添加普通成员
- Then 该用户出现在成员列表且角色为 member

**AC-C2.2**
- Given 我是 owner，成员列表包含 member
- When 移除该成员
- Then 该用户不再能访问此项目，列表立即移除

**AC-C2.3**
- Given 我是普通成员
- When 尝试添加或移除成员
- Then 操作入口不可用，接口返回无权限

#### REQ-C3 owner 转让

**AC-C3.1**
- Given 我是 owner，成员列表有其他成员
- When 选择某成员转让 owner
- Then 该成员变为 owner，我变为普通成员，owner 数量仍为 1

**AC-C3.2**
- Given 转让完成后
- When 我（原 owner）尝试删除项目或移除成员
- Then 操作被拒绝

#### REQ-C4 owner 可管理项目

- 来源：原始需求 §3
- 描述：owner 可以管理项目（删除、编辑等）。

**AC-C4.1**
- Given 项目存在
- When 以 owner 或普通成员身份打开项目设置
- Then 只有 owner 看到编辑与删除入口

### D. 技能管理

#### REQ-D1 上传技能

- 来源：原始需求 §4

**AC-D1.1**
- Given 我是项目成员
- When 上传技能包（含 `SKILL.md` 的目录或 zip）
- Then 技能出现在技能列表，版本号为 1

**AC-D1.2**
- Given 已有技能
- When 再次上传同名技能
- Then 生成新版本（版本号 +1），旧版本可下载，节点可用技能默认使用最新版本

#### REQ-D2 删除技能受引用约束

**AC-D2.1**
- Given 技能被一个仍在执行中的需求节点引用
- When 删除该技能
- Then 删除被拒绝，并列出引用它的需求与节点

**AC-D2.2**
- Given 技能未被任何未完成实例引用
- When 删除该技能
- Then 删除成功，历史已完成需求的输出不受影响

### E. 流程管理

#### REQ-E1 流程增删改查

- 来源：原始需求 §5

**AC-E1.1**
- Given 我是项目成员
- When 创建/重命名/删除流程
- Then 变更生效；被需求引用的流程不能删除

#### REQ-E2 节点列表与排序

**AC-E2.1**
- Given 流程有多个节点
- When 拖动列表项上下移动
- Then 顺序改变并保存，执行顺序即列表顺序

**AC-E2.2**
- Given 流程有多个节点
- When 点击某节点
- Then 该节点展开显示其输入、输出与可用技能配置

#### REQ-E3 节点输入定义

**AC-E3.1**
- Given 编辑节点
- When 输入类型选择「自由输入」
- Then 不展示固定输入项；执行时整个节点只有一个上传入口

**AC-E3.2**
- Given 编辑节点
- When 输入类型选择「固定输入」
- Then 可添加/删除固定输入项，每项配置名称、说明、文件类型、是否必填

#### REQ-E4 节点输出定义

**AC-E4.1**
- Given 编辑节点
- When 添加输出项
- Then 每项配置名称、稳定键、说明、文件类型、是否必填；输出项只能新增/删除，没有"自由输出"模式

#### REQ-E5 节点可用技能（多选）

- 来源：原始需求 §5、修正 M3

**AC-E5.1**
- Given 编辑节点
- When 打开可用技能选择
- Then 列出本项目全部技能，可多选，并保持选择顺序

**AC-E5.2**
- Given 节点已选择多个技能
- When 执行该节点的需求
- Then 模型上下文中包含全部所选技能（按顺序），且每个技能按其自身版本加载

### F. 需求管理与节点执行

#### REQ-F1 需求增删改查

- 来源：原始需求 §6

**AC-F1.1**
- Given 我是项目成员
- When 创建需求并选择项目内一个流程
- Then 需求创建成功，立即生成流程实例，当前节点为流程第一个节点

**AC-F1.2**
- Given 我创建了需求
- When 编辑需求标题/描述
- Then 修改生效；他人只能查看不能编辑

**AC-F1.3**
- Given 我是需求创建人
- When 删除需求
- Then 需求及其节点实例、会话对应关系一并移除（文件按留存策略保留或清理，见架构文档）

#### REQ-F2 需求绑定一个流程

**AC-F2.1**
- Given 创建需求页面
- When 选择流程
- Then 只能单选一个流程；创建后流程不可更换

**AC-F2.2**
- Given 需求已创建
- When 流程模板后续被修改
- Then 已有需求的节点、输入项、输出项、技能不受影响

#### REQ-F3 需求流程实例查看

**AC-F3.1**
- Given 打开自己或他人的需求
- When 查看需求详情
- Then 可见完整节点列表与每个节点状态（已完成/进行中/未开始），并显示当前节点

#### REQ-F4 节点信息页（当前节点）

- 来源：原始需求 §6、【重要！核心！】

**AC-F4.1**
- Given 我是需求创建人且打开当前节点
- When 查看页面
- Then 顶部仅有两个页签「会话」「节点信息」，无其他页签

**AC-F4.2**
- Given 当前节点
- When 查看「节点信息」页签
- Then 自上而下依次为：节点名称、上一节点输出、节点输入、输出项、说明

**AC-F4.3**
- Given 节点输入类型为自由输入
- When 查看「节点输入」区块
- Then 「节点输入」标题右侧出现上传按钮，上传后的文件列在区块内

**AC-F4.4**
- Given 节点输入类型为固定输入
- When 查看「节点输入」区块
- Then 逐项列出输入项，每个输入项右侧各有一个上传按钮

**AC-F4.5**
- Given 某个输出项已完成
- When 查看该输出项
- Then 其右侧出现下载按钮，点击可下载实际文件

**AC-F4.6**
- Given 全部必填输出项已完成
- When 刷新页面
- Then 需求自动进入下一节点；已是最后节点时需求状态变为已完成

**AC-F4.7**
- Given 上一节点存在输出
- When 查看当前节点
- Then 上一节点输出以可下载文件列表展示

#### REQ-F5 非当前节点只读

**AC-F5.1**
- Given 我打开的是非当前节点
- When 查看页面
- Then 不显示会话页签与输入框，节点信息只读（无上传、下载仍可用）

#### REQ-F6 对话驱动产出

- 来源：原始需求 §6
- 描述：对话时把节点输入、上一节点输出、本节点技能、本节点已有输出等引用给到模型，多轮对话补齐信息，最终完整输出指定输出项。

**AC-F6.1**
- Given 我是需求创建人且当前节点有上一节点输出与输入文件
- When 在会话中发起对话
- Then 模型上下文中包含节点信息、这些文件的真实路径与内容引用

**AC-F6.2**
- Given 模型按技能要求产出输出项
- When 模型提交输出项
- Then 文件写入固定目录并在页面「输出项」中可见、可下载

**AC-F6.3**
- Given 用户对产出不满意
- When 继续多轮对话要求修改
- Then 重新提交生成新版本，页面展示最新版本，历史版本不丢失

#### REQ-F7 会话页签

- 来源：原始需求 §6、修正 M1、M2、M4

**AC-F7.1**
- Given 我是需求创建人且打开当前节点
- When 点击「会话」页签
- Then **当前页面内**直接显示该需求的 DeepSeek Harness 原生会话（消息流、工具调用、输入框均由 DSH 组件渲染），页面不跳转、不离开工作台；切到「节点信息」页签时节点信息同样在当前页面内显示

**AC-F7.2**
- Given 需求已有多个会话
- When 打开会话页签
- Then 默认打开该节点的默认会话；会话视图顶部可切换到本需求其他会话

**AC-F7.3**
- Given 节点推进到下一节点
- When 打开新节点的会话页签
- Then 默认仍是同一个会话，可看到完整历史；用户亦可点击「新建会话」

**AC-F7.4**
- Given 某节点曾用过会话 A，之后新建了会话 B
- When 再次打开该节点
- Then 默认打开会话 B（节点的最近一次显式选择优先），仍可切换回会话 A

**AC-F7.5**
- Given 关闭 DSH 后重开
- When 进入需求
- Then 会话可以恢复（依据记录的会话标识重新打开），历史消息完整

### G. 内置指导技能

#### REQ-G1 节点默认注入指导技能

- 来源：原始需求 §7

**AC-G1.1**
- Given 任意节点
- When 模型开始工作
- Then 上下文包含指导技能，说明：输出什么、怎么输出、写到哪个路径才能被页面看到并可下载、如何跨会话与跨节点保存

**AC-G1.2**
- Given 指导技能与节点自定义技能同时生效
- When 查看模型可用技能

### H. 用户与权限

#### REQ-H1 注册登录

- 来源：原始需求 §8

**AC-H1.1**
- Given 未注册
- When 用任意用户名（密码可留空）注册
- Then 注册成功并可立即登录

**AC-H1.2**
- Given 未注册用户名
- When 尝试登录
- Then 登录失败并提示"用户不存在，请先注册"

**AC-H1.3**
- Given 用户名已注册
- When 用错误密码登录
- Then 登录失败；密码为空注册的用户只能用空密码登录

**AC-H1.4**
- Given 未登录或登录已过期
- When 访问任意业务接口
- Then 返回 401，页面跳转登录页

#### REQ-H2 成员读取权限

- 来源：原始需求 §9

**AC-H2.1**
- Given 我是项目成员
- When 查看项目内任意需求、流程、技能、成员
- Then 可见

**AC-H2.2**
- Given 我不是项目成员
- When 访问该项目任意资源
- Then 返回 403，不泄露资源是否存在

#### REQ-H3 owner 全权

**AC-H3.1**
- Given 我是 owner
- When 对项目内任意对象执行任意允许的操作
- Then 全部成功

#### REQ-H4 成员只能管理自己的数据

**AC-H4.1**
- Given 我是普通成员
- When 对他人创建的需求执行编辑或删除
- Then 返回 403

**AC-H4.2**
- Given 我是普通成员
- When 删除他人上传的技能或流程
- Then 返回 403；仅能删除自己创建的

#### REQ-H5 只能推进自己的需求

**AC-H5.1**
- Given 他人的需求且我打开其当前节点
- When 查看页面
- Then 与"非当前节点"一致：只读，无会话页签与输入框

**AC-H5.2**
- Given 我的需求
- When 上传节点输入、发起对话、提交输出、推进节点
- Then 全部允许

### X. 跨模块修正项

#### REQ-X1 多会话与需求级隔离（M1）

**AC-X1.1**
- Given 一个需求
- When 创建第二个会话
- Then 两个会话都归属该需求，互不混淆；其他需求看不到它们

**AC-X1.2**
- Given 会话列表
- When 查看
- Then 每个会话显示最后活跃时间，可按最近活跃排序

#### REQ-X2 节点新建会话绑定节点（M4）

**AC-X2.1**
- Given 我在节点 N 并点击「新建会话」
- When 创建完成
- Then 新会话归属本需求并设为节点 N 的默认会话，已有会话仍可切换

**AC-X2.2**
- Given 某人在节点 N 新建会话
- When 之后进入节点 N
- Then 默认打开这个新会话

## 6. 关键用户旅程

### 6.1 首次使用

```text
注册（用户名）→ 登录 → 项目中心 → 创建项目 → 自动成为 owner
→ 上传技能 → 创建流程（新增节点、定义输入输出、选择技能）
→ 创建需求（选择流程）→ 进入需求 → 当前节点 → 上传输入 → 与 Agent 对话
→ 模型产出输出项 → 页面下载 → 全部完成 → 进入下一节点 → … → 需求完成
```

### 6.2 协作

```text
owner 添加成员 → 成员登录 → 看到项目 → 创建自己的需求并推进
其他成员可查看该需求的全部节点与产出，但不能推进
```

## 7. 非功能需求

| ID | 类别 | 要求 |
|---|---|---|
| NFR-1 | 解耦 | Java 业务后端不依赖 DSH 任何包；插件 Client 只依赖官方公开扩展点（面板槽、会话工厂、Slot 服务），不改 DSH 源码 |
| NFR-2 | 升级 | DSH 升级后只需重装插件；业务端不变 |
| NFR-3 | 数据一致性 | 节点推进、输出登记在一个事务内完成；半提交不得推进 |
| NFR-4 | 真实性 | 页面不得展示尚未真实产生的输出；会话失效不得伪造历史 |
| NFR-5 | 安全 | `/internal/**` 仅接受预共享密钥且仅绑定本机；文件下载必须鉴权 |
| NFR-6 | 可部署 | 提供建库建表与变更脚本，可在其他环境一次性部署 |
| NFR-7 | 可用性 | 页面风格参考 GitHub：清晰的信息层级、可预期的列表与表单交互 |

## 8. 成功标准

1. 新用户从注册到产出第一个需求节点输出，全程无需手工写 SQL 或文件。
2. 同一项目下，owner 与成员看到的项目数据一致，权限差异符合第 5 节矩阵。
3. 卸载/禁用插件后，DSH 行为与官方版本一致。
4. 需求推进到第 N 节点时，仍能在会话中看到第 1 节点的完整对话历史（同一会话）。
