# 节点交付流程（workbench-node-delivery）

你在一个**需求节点会话**里。这个节点的产出必须写进固定目录并登记到工作台后端，
页面才会显示"已完成"并提供下载。下面每一步都不是可选项。

## 1. 先看清单，不凭记忆

调用 `node_context_get`（不带参数即可，它会认当前会话目录）。只看它返回的三块：

- 【输出项】：`itemKey`、类型、必填与否、是否已登记、**建议写入路径**；
- 【输入资料】：用户上传的原始资料在哪（相对路径）；
- 【上一节点】：上一个节点已经产出的文件。

**每一轮开始都重新拿一次**：用户可能刚上传了资料、别的会话可能刚提交了输出。
不要从对话历史里推断输出项，也不要猜 itemKey。

如果返回的节点状态不是"正在办理"，说明节点已经推进或是只读：
停下来告诉用户，不要再写文件、不要提交。

## 2. 信息不足时追问，不要编造

- 输入资料与用户描述是否足以支撑每个必填输出项？不够就**先问用户**，一次问清缺什么。
- 不编造事实、不虚构数据、不把"待确认"写成结论。确实无法确定的内容，
  在产出里标注"待确认"并写清楚需要用户确认什么。
- 节点绑定的技能（【生效技能】里列出的）如果与本任务相关，先用 `skill` 工具按名称加载，
  按技能里的方法做事；不要凭技能名猜测它的内容。

## 3. 引用资料先读，不要假设路径

- 要引用节点输入或上一节点输出时，用 `node_reference_read` 读：
  `kind` 取 `input`（本节点输入）、`previousOutput`（上一节点输出）、`ownOutput`（本节点已提交的输出），
  配 `itemKey` 或 `fileId`。
- 返回里出现「[已截断，剩余 N 字节]」时，说明还有内容没拿到；
  需要全文就用原生 `read` 工具读它给出的绝对路径，**不要编造剩下的部分**。

## 4. 每个输出项都必须用 node_output_write 写盘

- 唯一允许的写入方式是 `node_output_write`：`{ itemKey, fileName, content }` 直接给正文，
  或 `{ itemKey, fileName, sourcePath }` 把已有文件复制进输出目录。
- 不要用 `write` / `edit` / `bash` 往 `.workbench/` 或别的目录写交付物：
  这样写出来的文件没有经过扩展名与大小校验，页面也不会认。

### 文件名与扩展名：以输出项为准，不要自己起名

产物的**文件名由系统按输出项名称生成，你只需要指定扩展名**：

- 文件主名**固定等于输出项名称**（`node_context_get` 返回的 `name`），由工具自动套用。
  输出项叫「服务概述」时，产物就是「服务概述.md」——你不需要、也无法把它改成别的名字。
- 你唯一要决定的是**扩展名**，按该输出项要求的内容格式取：
  要求 JSON 就用 `.json`，要求 Properties 配置就用 `.properties`，
  要求 YAML 就用 `.yaml`，要求 Markdown 才用 `.md`，报表类通常 `.csv` 或 `.xlsx`。
- 给 `fileName` 时只写扩展名相关的部分即可（例如 `运行参数.json`），主名会被忽略并替换成输出项名称。
- **正文格式必须与扩展名一致**：写 `.json` 就输出合法 JSON，写 `.properties` 就输出键值对，
  不要出现"文件名是 .json、内容却是 Markdown 说明"这种错配——用户拿到文件会直接打不开。
- 输出项没有明确要求格式时，按内容本身最自然的格式命名，并在最后回复里说明用了什么格式。

工具返回 `relativePath` 和 `sha256`——**马上**把它们交给下一步，不要自己计算或改写。

## 5. 写完立刻登记

对每个 `node_output_write` 成功的输出项，**立即**调用
`node_output_commit`，参数就是刚才返回的 `{ itemKey, relativePath, sha256 }`。

- 不要攒到最后一起提交；也不要只写盘不登记（不登记 = 用户看不到、下载不到）。
- 提交结果里 `remainingRequiredOutputs` 非空 → 回到第 4 步做剩下的项。
- 结果里说"用户还没上传必填资料" → **不要重试提交**，
  直接告诉用户去节点信息页上传哪些资料。
- 提交失败（摘要不一致、路径不对等）→ 按错误提示**重新写一次**再提交，不要反复盲目重试。

## 6. 收尾必须向用户交代清楚

最后一条回复里写明白：

1. **已完成几项**（列出名称），**还剩几项**（列出名称与缺什么）；
2. 产出在哪看/怎么下载：工作台页面 → 当前需求 → 本节点的「节点信息」→「输出项」区块，点文件名下载；
3. 如果节点已推进，说下一个节点是什么、需要用户做什么；
4. 如果还缺用户提供的信息或资料，明确列出。

不要用"已完成"概括一切，也不要宣称提交了实际上没提交的项。
